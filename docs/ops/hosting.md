## 1. Architectural Distribution Boundaries (FD-160)

Per decision **FD-160** ([docs/plan/frontend/decisions.md](../plan/frontend/decisions.md)), the hosting architecture maintains a strict distinction between what operates locally inside the habitat and what is hosted publicly for judges and external review:

### What Stays on the Habitat LAN (Runtime System)

- **Hab Core Server:** Runs locally on Node.js with Fastify and `ws` at `0.0.0.0:8080` ([docs/specs/02_Technical_Requirements_Document.md](../specs/02_Technical_Requirements_Document.md) §A.5, §B).
- **Mission Clock & State Engine:** The authoritative mission clock (operating at 1×, 10×, or 60× sim speed), real-time simulation engine, WebSocket telemetry fan-out (≤ 10 Hz), and safety logic modules run strictly on the habitat server ([docs/specs/02_Technical_Requirements_Document.md](../specs/02_Technical_Requirements_Document.md) §D.14).
- **Local Asset Serving:** The server serves the web application build (`apps/web/dist`), tile pyramids (`data/sites/<site_id>/tiles/`), binary grids (`data/sites/<site_id>/grid/`), vectors (`vectors/`), and POI images (`images/`) directly over the habitat LAN ([docs/specs/02_Technical_Requirements_Document.md](../specs/02_Technical_Requirements_Document.md) §E.1).
- **Offline Integrity (NFR-01, NFR-08):** No internet connection is used or required at runtime. Astronaut suit tablets (SCR-12), HUDs (SCR-13), and ops consoles (SCR-11) connect exclusively to the Hab Core via the local travel router or Wi-Fi switch ([docs/ops/demo-kit.md](demo-kit.md)).

### Planned Submission Access

- **Public Replay Link (GitHub Pages):** A proposed static deployment of the web application (`apps/web`, package 27; [docs/specs/01_Product_Requirements_Document.md](../specs/01_Product_Requirements_Document.md) FR-34) hosted via GitHub Pages, serving the `#/replay` route.
- **Static Recording Data:** The intended public replay page reads a static recording (`scenarios/storm-sol4190/recording.json`) generated by `make record` (T27.05, T22.14, BD-105). It reproduces the sol 4190 storm timeline, crew telemetry, and alerts directly in the client browser without requiring a running Hab Core server or local network connection.
- **Large Site Bundle (Release Asset):** The complete site bundle (tiles, 5 m routing grid, and POI images) is distributed as a GitHub release asset tarball (team decision 2026-11-03, [docs/ops/feasibility.md](feasibility.md)), avoiding Git repository bloat.

## 2. Repository Visibility and Submission Access (FD-160 / FD-170)

1. **Repository Visibility Decision:**
   - Per the data lead's decision on 2026-11-08 (Obidit Islam), the development repository is kept private during construction ([docs/tasks/status.md](../tasks/status.md) T30.01).
   - The primary Space Apps submission artefact is a clean zip archive of the repository containing source code, documentation, scenarios, schemas, and vector data ([docs/ops/submission-checklist.md](submission-checklist.md)).
2. **Public Transition Rule (FD-160 / FD-170):**
   - If the official 2026 Space Apps Project Submission Guide published on 13 Nov mandates a public repository link for judging, the repository is switched to public only after running a verified `gitleaks`-free secrets scan ([docs/plan/frontend/decisions.md](../plan/frontend/decisions.md) FD-160).
3. **Public Link on Project Page:**
   - The project page should link to the GitHub Pages static recording view (`#/replay`) and to the code repository / archive once the team has published and verified them ([docs/ops/project-page.md](project-page.md)).

## 3. Team Release Asset Fetch Route

Team members and clean-clone environments download and verify the site bundle using the following documented procedure ([docs/ops/feasibility.md](feasibility.md)):

1. Sign in to GitHub CLI with an account having repository access. Download the site bundle release asset:

   ```sh
   gh release download data-gale_boxwork-2026.11.09 -p 'gale_boxwork-2026.11.09.zip' --repo tashobi02/CheesySpace-NasaSpaceAppChallenge
   ```

   Verify the downloaded zip SHA-256 against [the lane plan](../plan/README.md#6-environment-notes) before extracting it.

2. Unpack the downloaded bundle in a temporary directory for verification. Compare each file with `data/sites/<site_id>/site-manifest.json` ([docs/specs/05_Backend_and_Database_Schema.md](../specs/05_Backend_and_Database_Schema.md) §Site). For each asset, verify that the SHA-256 digest matches `sha256`.
3. If hashes match, extract the bundle contents into `data/sites/<site_id>/`, preserving the `tiles/`, `grid/`, `vectors/` and `images/` directory structure ([docs/specs/02_Technical_Requirements_Document.md](../specs/02_Technical_Requirements_Document.md) §E.1). Stop immediately if an asset is missing or a hash differs.

Obtain the bundle before running the full application. NFR-01 requires no internet at runtime; NFR-08 requires LAN-only operation without third-party requests ([docs/specs/02_Technical_Requirements_Document.md](../specs/02_Technical_Requirements_Document.md) §F). Downloaded datasets and large binaries are kept out of Git ([CLAUDE.md](../../CLAUDE.md) §2); `.gitignore` excludes site tiles, grid and images, while `vectors/` and `site-manifest.json` remain committed.
